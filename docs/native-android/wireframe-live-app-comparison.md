# Wireframe vs. Live App Reconciliation Comparison

Date: 2026-08-01  
Scope: Screen-by-screen reconciliation between the original Antigravity wireframe (`/wireframes`), live application (`com.collegedate.app` v2.2.36), web codebase (`src/pages/*`), and native Kotlin targets (`android-native/`).

---

## 1. Reconciliation Classification Framework

Every identified discrepancy is categorized using one of seven explicit decision classifications:
1. `Keep live version`: Live production implementation takes precedence (e.g. backend RPC integration, RevenueCat billing).
2. `Keep wireframe version`: Original wireframe layout takes precedence (e.g. thumb-zone reachability, clean card hierarchy).
3. `Merge both`: Combine best visual elements from wireframe with live application functionality.
4. `Redesign for native Android`: Replace web-wrapper patterns with native Jetpack Compose / Material 3 Android paradigms.
5. `Product-owner decision required`: Requires explicit product confirmation before implementation.
6. `Remove because obsolete`: Feature or wireframe artifact is outdated or superseded.
7. `Defer because behavior is unclear`: Postpone implementation until requirement is clarified.

## 3. Key Decisions & Recommendations Summary

1. **Adopt "Merge Both" Strategy**: Combine the superior visual ergonomics and thumb-zone reachability of the Antigravity wireframes with the robust backend RPCs, RevenueCat monetization, and real-time presence of the live production app.
2. **Standardize Native Android Components**: Replace web UI controls (browser file inputs, web modals, CSS absolute positioning) with Jetpack Compose Material 3 components (`Scaffold`, `ModalBottomSheet`, `LazyColumn`, `HorizontalPager`).
3. **Preserve All Live Business Rules**: All 12 live app screens (Match, Inbox, Chat, Profile, Onboarding, Explore, Confessions, Leaderboard, Premium, Wallet, Referrals, Settings) preserve their exact Supabase tables, RPC contracts, and RevenueCat identifiers.
